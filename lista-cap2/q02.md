a) **Por que evitar `<conio.h>`:** Trata-se de uma biblioteca antiga, proprietária e não padrão (criada para MS-DOS/compiladores legados como Borland C). Ela não existe nativamente no GCC/Clang no Linux, macOS ou em ambientes POSIX, o que quebra a portabilidade do código.

b) **Funções equivalentes e portáveis:** As funções padrão da `<stdio.h>` para leitura e escrita de caracteres são `getchar()`, `fgetc(stdin)` e `putchar()`.

c) **Código de leitura robusto:**
```c
#include <stdio.h>

int main(void) {
    char c;
    printf("Digite um caractere: ");
    // O espaco antes do %c ignora quebras de linha ('\n') e espacos residuais no buffer
    scanf(" %c", &c);
    printf("Caractere lido: %c\n", c);
    return 0;
}
